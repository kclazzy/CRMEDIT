# Техническое задание: CRMEDIT — редактор-конструктор CRM на Rust

Версия 0.2 · 15.11.2026

## 1. Исходный запрос

> Редактор CRM на языке Rust. Пользователь должен легко и быстро выстраивать
> систему, а в конце должен выходить готовый установочник Windows и программа
> для работы. Должны быть истории проектов в каждой отдельной папке, если
> необходимо между ними переключаться.

## 2. Критический разбор запроса и внесённые правки

| № | Исходное условие | В чём проблема | Правка, принятая в ТЗ |
|---|---|---|---|
| 1 | «На выходе установочник и программа» | Если редактор будет генерировать исходный код и компилировать его, каждому пользователю понадобятся компилятор Rust и сборочные инструменты (гигабайты, минуты сборки, хрупкость). | Рабочая CRM — это **та же заранее собранная программа**, что и редактор: она читает **описание CRM** (данные), дописанное в конец её файла. «Сборка» = копия программы + описание. Компилятор пользователю не нужен, сборка занимает меньше секунды. |
| 2 | «Установочник Windows» | NSIS/Inno Setup/WiX — внешние программы, которые пришлось бы ставить отдельно; с ними редактор перестаёт быть самодостаточным. | Установочник делает сам редактор, и это тот же файл: программа с описанием внутри, запущенная не из папки установки, показывает окно установки, а установленная — работает как CRM. Внешние инструменты не требуются. |
| 3 | То же | Неподписанный `.exe` вызывает предупреждение Windows SmartScreen. Запрос об этом молчит. | Установка — в профиль пользователя, права администратора не нужны. Подпись кода **пока не реализована** (см. раздел 11): описание лежит в конце файла, а подпись меняет конец файла, поэтому для подписи описание нужно перенести в ресурс программы. |
| 4 | «Легко и быстро» | Неизмеримо, нельзя принять работу. | Измеримые критерии: рабочая CRM из шаблона — не более 5 минут и без единой строки кода; любая правка схемы — не более 3 действий; сборка установочника — не более 10 секунд. |
| 5 | «Истории проектов в каждой отдельной папке» | Неоднозначно: история изменений или список проектов? Нужен ли git? | Принято: **проект = одна самодостаточная папка**, в ней же лежит его **история версий** (снимки). Git не требуется. Папку можно скопировать, перенести, заархивировать — история переедет вместе с ней. Отдельно — **реестр проектов** для быстрого переключения. |
| 6 | История | Откат, который стирает более поздние версии, ведёт к потере работы. | История только дополняется. «Вернуться к версии N» = новый снимок с содержимым версии N. Потерять ничего нельзя. |
| 7 | Не сказано об обновлении | CRM поставили, в ней накопились клиенты, затем схему поменяли. Что с данными? Это главный риск всего продукта. | Обязательное требование: новая версия CRM при установке поверх старой **переносит данные без потерь**. Удаление поля/сущности в редакторе не удаляет данные у клиента, а скрывает их. Идентификаторы сущностей и полей неизменяемы; меняется только отображаемое название. |
| 8 | Не сказано о числе пользователей CRM | «CRM» обычно подразумевает совместную работу, а это сервер, учётные записи, права — на порядок больший объём. | Версия 1 — **однопользовательская настольная** CRM с локальной базой. Совместная работа вынесена в этап 6 и проектируется отдельно. Общий сетевой диск как замена серверу запрещён (порча базы). |
| 9 | Не сказано о скриптах/формулах | Произвольный код в описании CRM = уязвимость и неотлаживаемые ошибки у конечного пользователя. | В версии 1 описание CRM — только данные: сущности, поля, связи, воронки, представления. Скриптов нет. |
| 10 | «На языке Rust» | Интерфейс на веб-технологиях (Tauri) добавил бы второй язык и зависимость от WebView2. | Интерфейс редактора и исполнителя — `egui` (чистый Rust, один `.exe` без зависимостей). Плата: вид не «родной» для Windows; принимается ради простоты поставки. |
| 11 | Не сказано о целевых ОС редактора | — | Редактор и CRM — Windows 10/11 x64. Ядро не зависит от ОС и проверяется автоматически на Linux и Windows. |

## 3. Словарь терминов

| Термин | В коде | Значение |
|---|---|---|
| Описание CRM | `Definition` | Полное описание одной CRM-системы: название, сущности, их поля. Только данные. |
| Сущность (в окнах — «раздел») | `Entity` | Вид записей: «Клиенты», «Сделки», «Задачи». |
| Поле | `Field` | Свойство сущности: «Телефон», «Сумма». |
| Вид поля | `FieldKind` | Текст, число, дата, флажок, выбор из списка, ссылка на сущность. |
| Идентификатор | `Ident` | Неизменяемое техническое имя сущности или поля (`client`, `phone`). Латиница в нижнем регистре, цифры, `_`. |
| Название | `title` | Отображаемое имя, меняется свободно. |
| Проект | `Project` | Папка с историей версий одного описания CRM. |
| Снимок | `Snapshot` | Неизменяемая версия описания: номер, время, примечание, описание. |
| Текущая версия | head | Снимок с наибольшим номером. |
| Реестр проектов | `Registry` | Список известных папок проектов; первый в списке — активный. |
| Рабочая CRM | `crm-runtime` | Окно и база данных, построенные по описанию. |
| Идентификатор CRM | `app_id` | Постоянное имя CRM (`crm_…`): папка установки, папка данных, запись об удалении. Вычисляется из первого снимка проекта и потому не меняется. |
| Комплект | `Bundle` | То, что дописано в конец программы: идентификатор CRM, номер версии, описание. |
| Сборка | build | Копия программы с комплектом в конце — установочник. |
| Запись, значение | `Record`, `Value` | Строка данных в рабочей CRM и значение одного её поля. |
| Доска | board | Показ записей колонками по вариантам поля «выбор из списка». |

## 4. Состав продукта

Пользователь получает два файла:

1. **`crmedit.exe`** — программа с окном. Одна и та же программа играет три роли:
   - без описания внутри — **редактор**;
   - с описанием, запущенная из «Загрузок» — **установщик** (или обновление);
   - с описанием, запущенная из папки установки — **рабочая CRM**.
2. **`crmedit-cli.exe`** — те же действия редактора из командной строки, для автоматизации.

Роль выбирает одна чистая функция (`launch::role`), поэтому её поведение проверяется автотестами полностью.

## 5. Функциональные требования

### 5.1. Проекты и история

- П-1. Проект — одна папка. Структура:
  ```
  <папка проекта>/
    history/
      000001.json         снимок № 1: версия формата, время, примечание, описание CRM
      000002.json         снимок № 2 …
  ```
  Отдельного файла-признака нет: проект существует ровно тогда, когда существует снимок № 1. Поэтому создание проекта — одна атомарная операция, «полусозданного» проекта не бывает.
- П-2. Каждое сохранение создаёт новый снимок. Сохранение без изменений снимка не создаёт.
- П-3. Снимки никогда не изменяются и не удаляются средствами редактора.
- П-4. Возврат к версии N создаёт новый снимок с описанием из версии N.
- П-5. Запись снимка атомарна: при сбое питания проект остаётся на предыдущей версии. Два одновременно открытых редактора не могут затереть снимки друг друга — второй получает ошибку «проект изменён, перечитайте».
- П-6. Реестр проектов хранится в профиле пользователя, упорядочен по времени последнего открытия. Переключение проекта — одно действие. Пропавшая папка не ломает реестр: помечается как недоступная.
- П-7. Проект открывается и без реестра — указанием папки.

### 5.2. Построение CRM

- К-1. Новый проект создаётся из шаблона («Продажи», пустой). Шаблон «Продажи» сразу даёт рабочую CRM: клиенты, сделки, задачи.
- К-2. Действия над сущностями: добавить, переименовать (название), скрыть и вернуть, изменить порядок. Удаления нет (правка 7): ошибочно добавленное убирается возвратом к предыдущей версии.
- К-3. Действия над полями: добавить, переименовать (название), скрыть и вернуть, изменить порядок, пометить обязательным.
- К-4. Виды полей: текст, число, дата, флажок, выбор из списка, ссылка на сущность.
- К-5. Невозможно сохранить некорректное описание: повторяющиеся идентификаторы, ссылка на несуществующую сущность, пустой или повторяющийся список вариантов, скрытие сущности, на которую ссылается видимое поле. Ошибка сообщается сразу и по-русски, с указанием места.
- К-6. Предпросмотр: редактор показывает настоящую рабочую CRM с пробными данными, без сборки. Пробные данные лежат в папке проекта (`preview-data/`) и переживают правки структуры.
- К-7. Технические имена пользователь не вводит: они подбираются по русскому названию («Дата закрытия» → `data_zakrytiya`).
- К-8. Доска по этапам: для любого раздела с полем «выбор из списка»; карточки переносятся между колонками. Поиск по всем полям.

### 5.3. Исполнитель (рабочая CRM)

- И-1. По описанию показывает список сущностей, таблицу записей, форму записи; создание, изменение, удаление, поиск.
- И-2. Данные — локальная база SQLite в профиле пользователя (`%APPDATA%\<идентификатор CRM>\crm.db`), отдельно от программы.
- И-3. При запуске с более новым описанием переносит базу: добавляет таблицы и столбцы, ничего не удаляет. Перенос идемпотентен: прерванный и запущенный повторно, он приводит к тому же результату. Если поле в новой версии хранит данные другого рода (текст стал числом), перенос отклоняется целиком и база не меняется.
- И-4. Перед переносом делает резервную копию базы.
- И-5. Экспорт и импорт CSV (разделитель «;», UTF-8 с меткой — открывается в Excel). Импорт — «всё или ничего» с перечнем ошибок по строкам.
- И-6. Запись, на которую ссылаются другие записи, удалить нельзя.

### 5.4. Сборка и установочник

- С-1. Сборка — одно действие в редакторе; результат — один файл `<Название CRM>-setup.exe`.
- С-2. Установочник: ставит CRM в профиль пользователя, создаёт ярлыки в меню «Пуск» и на рабочем столе, регистрирует удаление в «Программы и компоненты».
- С-3. Установка поверх существующей версии обновляет программу и описание, данные сохраняет.
- С-4. Удаление по умолчанию оставляет данные; удаление данных — отдельный явный выбор.
- С-5. Подпись кода — не реализована (раздел 11).
- С-7. Комплект защищён контрольной суммой: повреждённый при скачивании установочник сообщает об этом, а не ставит испорченную CRM.
- С-6. Сборка воспроизводима: одна версия проекта → побайтно одинаковый установочник.

## 6. Нефункциональные требования

- Н-1. Скорость: CRM из шаблона до установочника ≤ 5 минут; сборка ≤ 10 с; запуск редактора ≤ 2 с. (Сборка — копирование одного файла, укладывается с запасом; остальные два показателя на живой Windows ещё не замерялись.)
- Н-2. Редактор, исполнитель, установочник — по одному `.exe`, без установки сред выполнения.
- Н-3. Язык интерфейса — русский. (Сбор строк в одном месте для перевода на другие языки отложен: второго языка пока никто не просил.)
- Н-4. Работа без сети. Никакой телеметрии.
- Н-5. Формат проекта версионируется; новые редакторы открывают старые проекты. Старый редактор отказывается открывать проект более нового формата, а не портит его.
- Н-6. Качество: бизнес-логика — чистые функции в `crm-core`, покрытые тестами поведения; тесты, `clippy` без предупреждений и сборка под Windows выполняются автоматически при каждом изменении.

## 7. Архитектура

```
crates/
  crm-core/     описание CRM, проверка, проекты, история, реестр — без окон и без базы
  crm-runtime/  рабочая CRM: значения, база SQLite и перенос, действия (Crm), окно (CrmApp)
  crmedit/      редактор (окно и командная строка), комплект, установка, выбор роли
ci/
  windows-e2e.ps1  сквозная проверка на настоящей Windows
```

Принципы:

- Некорректное описание нельзя построить: поля структур закрыты, изменение — только через проверяющие операции, чтение файла — через ту же проверку.
- Внешние данные проверяются один раз на входе (файл, аргументы, ввод в форму, CSV), внутри им доверяют.
- Один писатель на проект, обеспеченный файловой системой: снимок создаётся операцией «создать, только если не существует».
- Окна только рисуют и передают действия: вся логика — в функциях без окна, а сами окна проверяются тестами через дерево доступности (нажатия, ввод текста, выбор из списков).
- Всё внешнее передаётся явно: часы, папки профиля, диалоги выбора файлов, исполнитель PowerShell. Поэтому установка проверяется и без Windows, а на Windows — сквозным сценарием в CI.
- Формат файлов проекта — JSON: читается человеком, сравнивается, чинится вручную.

## 10. Открытые вопросы к заказчику

1. Верно ли понята «история в папке» (правка 5)? Если имелся в виду только список недавних проектов — история версий всё равно остаётся, она ничего не стоит пользователю.
2. Нужна ли совместная работа нескольких сотрудников с одной базой? От этого зависит, появится ли этап 6 и когда.
3. Есть ли сертификат подписи кода? Без него покупатели CRM увидят предупреждение SmartScreen.

## 11. Известные ограничения

1. **Нет подписи кода.** Windows SmartScreen предупредит при первом запуске и редактора, и собранного установочника («Подробнее» → «Выполнить в любом случае»).
2. **Копия папки проекта — та же CRM.** Идентификатор CRM вычисляется из первого снимка, поэтому две CRM, выросшие из копии одной папки, установятся в одну папку и разделят данные. Новую CRM нужно начинать кнопкой «Новый проект», а не копированием.
3. **Размер.** Каждый установочник содержит всю программу целиком, включая неиспользуемый в CRM код редактора.
4. **Время в истории показывается в UTC.**
5. **Тёмная или светлая тема** берётся из настроек системы, своего переключателя нет.
6. **Удалить поле или раздел нельзя** — только скрыть (правка 7); ошибочно добавленное убирается возвратом к прежней версии.
